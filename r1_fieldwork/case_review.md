## 원자료 확인 및 범위 선정

- 기존 B2B 시스템·작은 수정 계층·승인 경로 하나로 경계를 정했는가:
- 실제 사용된 runbook의 버전, 예외 처리, 담당자 가용시간, 기존 backlog는 무엇인가:
- baseline에서 예정된 개선·인력 변경·정상 운영자의 적응을 어디까지 재현하는가:
- 모든 핵심 증거의 artifact id / locator / 확인한 주장 / 불확실성:
- 실제 변경 최소 한 건의 전·전환 중·후를 연결한 자료 / 변경 시점·적용 대상·구/신 버전 / 공유 범위 확인:
- π₀를 복원할 수 없는 사유가 있는가. 미확인과 복원 불가능을 구별했는가:
- 인터뷰의 성공·실패·중단 여부와 무관하게 복원 가능성을 비교했는가:
- 미선정 후보별 사유와 조사 접근성 편향은 무엇인가:

총점을 만들지 않는다. 증거의 시간적 연결, baseline 행동의 관측 가능성, 구현 범위가 가장 명확한 프로젝트 하나를 선택하고 이유를 기록한다. 같은 원자료의 여러 변형이나 저작물은 독립 사례군 수를 늘리지 않는다.

## 구현 전 고정할 검증계획

- 연구에서 답할 질문과 추정 대상: 고정된 도착 workload에서의 통제 환경 기여인지, 실제 배치의 총효과인지:
- 개입 전 운영기간 / 데이터 버전·해시 / 관측 단위와 식별자 / 익명화가 보존·변경한 구조:
- 보정용 기간 / 보류 검증 기간 / 분리 이유 / 경계 backlog 초기화 / 누출 방지:
- 보류 자료를 열기 전에 고정할 지표·정의·단위·집계 구간·계층·허용오차·근거:
- 누락/취소/재작업/중복/미완료 거래의 처리 규칙과 분모:
- 실제 직원의 판단을 규칙으로 옮기며 빠지는 행동과 그 근거:
- 외생 입력: 도착 사건, 외부 장애 등. 정책 결과: 라우팅, 처리시간, escalation, 재작업 등. 각 필드의 분류:
- 알려진 유익한 정책의 근거 / 허용되는 코드·설정 변경 / 관측 밖 개입의 처리:
- 실제 개입 반응을 뒷받침하는 실험·운영자료 또는 메커니즘 검사 / 아직 검증 못 한 부분:
- 과거 개입 구간의 입력·처리경로·결과 / 비교 가능한 미변경 구간·단계적 배포·롤백 / 동시 변경과 외부 충격 / 대안 원인:
- 개입 구간의 보정·보류 구분 / 관측된 정책 변화가 허용할 AI 변경과 공유하는 메커니즘 / 관측 범위 밖 변경:
- 승인 상태가 실행 경로에 반영되는 방식 / 독립 결과 원장·품질 검사의 위치:
- 인계 시점·권한 종료 / 고정된 운영자 역할·노동 집계 / 충격 두 개와 선정 이유:

허용오차는 결과를 보고 완화하지 않는다. 평균 하나가 맞아도 오류율·escalation·혼잡 구간·꼬리 지연 등 주요 동작이 틀리면 해당 용도의 검증을 보류한다. 희소 사건 자료가 부족하면 미판정으로 남긴다. 보류 자료로 튜닝했다면 새 검증 자료가 필요하며, 없으면 보류 검증 통과라고 부르지 않는다.

과거 처리결과를 정답처럼 재생해 점수를 맞추지 않는다. 실제 runbook이 입력에 반응해 결과를 생성해야 한다. 개입이 바꿀 라우팅·재작업·수요까지 외생 입력에 고정하면 해당 효과를 제거한다. 수요를 고정하는 첫 실험은 그 조건부 효과로 범위를 제한한다.

## 실행 뒤에만 채울 결과

- baseline 검증: 고정된 코드/설정 버전, 실행 명령, 보류 workload 해시, 지표별 관측·재현값·오차·판정:
- 개입 검증: 변경 diff, 실제 transaction 경로와 품질 변화, 허용 개입 범위 밖 동작:
- 인계 검증: FDE 개입 중단 후 충격 2개, 정상 운영 노동과 추가 구조 노동, 실패를 포함한 결과:
- 반사실 비교: π₀와 πA에 공유한 외생 사건·초기 backlog, 정책 때문에 달라진 결과, 비용:
- 미검증 요인 및 허용할 주장:

baseline 재현은 개입 효과 식별의 충분조건이 아니다. 같은 baseline을 설명하는 모델도 개입 뒤 예측은 다를 수 있다. 반응 메커니즘에 근거가 없으면 통제 시뮬레이션 내 결과로 보고하고 현실 ROI나 FDE 대체로 해석하지 않는다.

이번 첫 사례 선정에서는 관측된 실제 변경 전후 자료를 개입 검증의 최소 요청 자료로 둔다. 자료가 없으면 인터뷰는 보존하고 해당 검증은 보류한다. 전후 자료 하나만으로 효과가 식별됐다고 하지 않는다. 관측된 과거 정책의 반응을 재현해도 새 AI 정책 전체가 검증된 것은 아니며, 근거가 있는 메커니즘·조건으로 해석을 제한한다.

## 완료 조건과 후속 단계

인터뷰 완료 / 자료 검토 / 프로젝트 선정 / twin baseline 검증 / 개입·인계 검증을 별도 기록한다. baseline을 구현할 때는 선정 기록이 필요하고, AI 평가를 붙이기 전에는 baseline 검증과 알려진 정책 검사가 필요하다. 첫 사례군 수 1은 전체 실행 경로와 두 인계 충격까지 실제 검증한 뒤에만 기록한다.

첫 환경 검증은 벤치마크 개발의 중간 단계다. 그 뒤 공통 실행기에 실제 모델·에이전트를 연결하고 반복 실행·비교·재현 패키지를 완성한다. 사람의 비교 실험이나 독립 두 번째 저작팀을 첫 환경 구현의 선행 조건으로 요구하지 않는다. 검증한 사례 범위의 모델 비교와 향후 R2·R3의 [인간 비교 연구](../human_evaluation_decision.md)는 구분한다. 같은 원자료의 독립 저작 검증은 일반적인 능력 순위 해석의 게이트이며, 저작팀 일치가 독립 사례 수·통계적 검정력·다른 조직 전이의 근거를 추가하지 않는다.

검증 목적과 허용오차를 초기에 정하는 원칙은 [Sargent, WSC 2013](https://informs-sim.org/wsc13papers/includes/files/027.pdf)의 용도별 모델 검증 논의에 따른다. 위 조사·선정 세부 규칙은 이 프로젝트의 구현 선택이며 해당 논문에서 FDE-Bench를 검증한 것은 아니다.
