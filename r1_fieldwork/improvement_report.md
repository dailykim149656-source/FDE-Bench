# 개선 점검 기록

대상: R1 조사 도구의 수정 이력과 2026-09-08 주장·우선순위 정정. 연구 프로토콜 v0.3나 baseline twin은 추가하지 않았다.

**아래 여덟 결함의 공통 원인은 출력의 이름이 실제 확인한 근거보다 더 많은 것을 주장한 것이다.** 빈 오류 목록을 통과, 문장 수를 가치, 실패를 부적격, 읽기 실패를 부재, 미확인을 false, 실행 완료를 검증, baseline 적합을 개입 타당도로 승격했다. 이후 감사의 첫 질문은 “이름이 근거를 앞지르는가”다.

## 발견한 문제와 수정

| 문제 | 재현·근거 | 적용한 수정 |
|---|---|---|
| 근거 없는 통과 | 기존 적격 fixture의 artifacts를 비우고 draft로 바꿔도 hard_fails가 빈 배열을 반환했다. | 자료 파일, 근거 위치, 해시와 baseline 주장 연결을 확인한다. 결과 이름은 READY_FOR_REVIEW이며 선정·타당도 인증이 아니다. |
| 임의 점수로 자동 선정 | runbook 문장 수와 지표 수, 코드와 설정의 동시 변경 등에 점수를 더했다. | 점수·정렬·자동 pick을 제거하고 후보별 자료 상태와 사람의 선정 근거를 남긴다. |
| 성공 사례만 남기는 조건 | held_on_next_workload=false라는 이유로 후보가 탈락했다. | 실제 배치의 실패·중단·인계 붕괴는 관측 결과로 보존한다. 첫 환경의 유익한 정책 검사는 별도다. |
| 입력 오류의 은폐 | 잘못된 UTF-8 실사례 파일이 조용히 목록에서 사라졌다. string flag와 boolean metric도 통과했다. | 명시적 형식 검사와 INVALID/종료 코드 2. 현재 입력 양식은 숫자 점수를 산출하지 않는다. |
| fixture의 실사례 유입 | 기존 선택기는 status와 자료의 생성 출처를 검사하지 않았다. | 합성 출처 또는 fixture 상태면 EXCLUDED. 사례 폴더로 옮겨도 같은 처리. 거짓 출처 표기를 완전히 탐지한다는 뜻은 아니다. |
| 미확인과 불가능의 혼동 | 기본 false 값이 곧 탈락으로 연결됐다. | null·초안·미수집은 INCOMPLETE. 복원 불가능은 이유를 기록하고 OUT_OF_SCOPE로 구분한다. |
| 자기검사로 보이는 출력만 존재 | 기존 fixture PASS/DROP은 예상 결과를 assert하지 않았다. | 임시 자료로 실제 CLI를 실행해 오판 시 실패하는 회귀검사를 추가했다. |
| baseline 적합의 과해석 | 기존 안내는 baseline 재현 뒤 개입 효과 비교로 바로 넘어갈 여지가 있었다. | 보정/보류 검증 분리, 사전 허용오차, 외생 입력과 정책 결과 구분, 허용 개입 메커니즘과 관측 밖 한계를 사례 검토표에 추가했다. |

## R1 도구 수정 당시의 검증 이력

- 임시 합성 입력을 사용하는 CLI 회귀검사 46개 통과. 실제 인터뷰를 추가하지 않는다.
- 빈 실제 cases 디렉터리: records=[], selected_case=null. twin fidelity와 사례군 수는 NOT_ASSESSED.
- 기본 CLI·--help·JSON 출력·잘못된 인수의 동작을 확인했다.
- Python 소스 컴파일과 Ruff 검사를 수행했다. 5개 관점의 에이전트 검토 기록은 review_results.json에 남긴다. 해당 PASS는 기록된 파일 스냅샷의 코드·문서 검토이며 과학적 타당도나 이후 문서 수정의 검증이 아니다.
- debugger에서 실제 cases 경로와 scan의 빈 결과 반환을 관찰했다.
- 당시 archive의 v0.1/v0.2는 Downloads 원문과 바이트 단위 일치했다. 이번에는 archive v0.2에 명시적 정정 주석을 붙였고 Downloads 원문과 원 해시는 보존했다.
- 이 R1 수정 당시에는 원 R0 추정기와 results.json을 확보하지 못해 재실행하지 못했다. 이후 사용자 제공 ZIP으로 원본을 복구했고, 2026-09-08 별도 R0 실행에서 20/20 및 원 수치 일치를 확인했다. [복구 기록](../r0_recovery.md)이 해당 근거이며 과거 R1 검토의 범위를 소급해 늘리지 않는다.

## 산출물 명칭 감사 — 2026-09-08

| 이름·상태 | 실제로 확인하는 것과 현재 해석 |
|---|---|
| FDE-Bench / R0_REFERENCE_REPRODUCED | 구현 사례는 0개다. 복구한 원 코드의 합성 검사 20/20과 원 수치 일치를 확인했다. 실제 twin·개입 타당도 검증은 아니다. 원 출력의 passed는 이 범위로만 읽는다. |
| seeds_per_looped_check=1000 / “동등 구현” | 원 필드명·요약에 대한 해석 제한이다. 1,000 seed 검사는 01–06·09–10이며 11은 100개, 나머지는 단일 fixture나 파라미터 검사다. 15는 동일 정책의 이름만 바꾼다. 코드와 과거 출력은 보존하고 재현 메타데이터에 실제 범위를 적었다. |
| select_case.py / READY_FOR_REVIEW | 파일명은 과거 명칭이다. 현재 기능은 자료 준비 검사이며 선정하지 않는다. 전후 자료 내용·인과 식별·진위는 사람이 확인해야 한다. |
| INVALID / EXCLUDED / OUT_OF_SCOPE | 각각 입력 해석 오류, 합성 입력 제외, 잠정 첫 환경 범위 밖이다. 실제 프로젝트 자체가 가치 없거나 거짓이라는 판정이 아니다. |
| source.origin=observed / reconstructable=true / collected | 기록 작성자의 출처·판단·수집 상태 선언이다. 검증된 실사례·복원 성공을 뜻하지 않는다. |
| schema_version=2 / 8개 sections / case_review.md | 실무 검토 전 잠정 형식과 미작성 서식이다. 첫 2–3건 후 수정할 수 있으며 환경 축 확정이 아니다. |
| eligible_shape.json / ineligible_opinion_only.json | 과거 테스트 파일명이다. 둘 다 fixture/synthetic으로 EXCLUDED되며 실사례 적격/부적격의 예가 아니다. |
| self_check 통과 / review_results의 PASS / review_snapshot 해시 | 각각 합성 CLI 회귀검사, 특정 스냅샷의 에이전트 검토, 파일 동일성이다. R0·현장자료·벤치 타당도 근거가 아니다. 기존 검토는 역사 스냅샷으로 표시했다. |
| selected_case=null / case_family_count=NOT_ASSESSED | 이 도구는 선정·구현 사례 수를 판정하지 않는다. 실제 프로젝트 상태의 구현 수 0과 구분한다. |
| baseline 적합 / 알려진 정책 재현 | 각각 관측된 기존 운영·특정 정책 조건에 대한 재현 근거다. 새 AI 개입이나 현실 총효과 전반의 보장이 아니다. |
| 연락 목록 / 인터뷰 요청문 / 인간 평가 결정문 | 빈 후보 기록, 미발송 초안, 연구 범위 결정이다. 연락·모집·인터뷰 완료나 인간 비교 결과가 아니다. |
| 독립 저작팀 / 독립 사례군 | 전자는 같은 원자료에 대한 저작 민감도를 검사한다. 저작팀 수를 독립 고객 사례 수나 검정력으로 세지 않는다. |

기존 CLI·fixture 파일명은 이번에 변경하지 않았다. 자료 접근보다 도구 정비를 앞세우지 않으며, 사용 설명에는 실제 기능·합성 출처를 표시한다. 다음에 산출물을 내보낼 때는 제목·열 이름·상태 옆에 **확인한 주장, 근거/버전, 미검증 범위**를 검토한다. 연구 결과에는 v0.2 §7.1·§11.1의 claim_scope·human_scope·organization_coverage·unvalidated_dimensions 및 해당 버전을 함께 기록한다. 근거가 없으면 수치를 만들거나 이름으로 대신하지 않는다.

## 이번 우선순위와 접근 제약

1. [R0 복구 완료](../r0_recovery.md): 제공된 ZIP의 원 파일 5개를 보존하고 Git에 기록했다. 원 코드로 20/20과 §13 수치를 재현했으며 v0.2 §0·§7.1·§13·§14A의 미검증 주석을 정정했다. 원 결과에도 source_sha256이 있었으므로 “원 코드 버전 근거가 없었다”는 해석은 정정한다. §11.1 식별자는 별도 재현 메타데이터로 보완했다.
2. [인간 에피소드 결정 정정](../human_evaluation_decision.md): “R1에서 연구 종료”는 사용자 목적을 잘못 해석한 문구로 철회했다. 목표는 모델·에이전트·하네스의 발전, 재귀개선, 실제 FDE 대체를 검증하는 벤치마크다. 인간 비교·현장 전이도 장기 목표에 포함하며 R2 인간 비교는 별도 비동기 다일 수행을 요구한다.
3. [자료 요청](outreach.md): 실제 변경 최소 한 건의 전·전환 중·후 자료, 적용 시점·대상·버전, workload·결과, 동시 변경·외부 충격을 추가했다. 연락 목록도 기록 보유·공유 담당 역할 중심으로 바꿨다.
4. 최초 인터뷰 2–3건: 접근 가능성과 잠정 분류를 확인한 뒤 질문표를 수정한다. 전체 5–6명 조사와 프로젝트 한 건 선정에 앞선 단계다. 인터뷰 전에 R1 도구 기능·스키마·검사를 더 확장하지 않는다.

**현재 임계 경로는 실제 회사의 변경 전후 운영자료에 대한 접근이다.** 인터뷰 상대·일정·공유 경로는 미확보다. 실제 인터뷰·선정 프로젝트·구현된 사례군은 여전히 0개다. 다음 외부 입력은 실제 runbook, 개입 전 관측자료, replay 가능한 workload와 실제 변경 전후를 연결한 기록이다. 검증계획의 실질 내용, 자료의 출처·시점, 허용오차는 사람의 자료 검토로 결정한다. 코드·문서 점검의 통과로 접근 대기 상태를 완료 처리하지 않는다.

관측된 기존 운영의 재현만으로 개입 반응이 식별되지는 않는다. 용도와 허용오차를 초기에 명시하는 원칙은 [Sargent (2013)](https://informs-sim.org/wsc13papers/includes/files/027.pdf)의 시뮬레이션 검증 논의에 따른다. 이 문서의 세부 조치는 FDE-Bench의 구현 선택이며 해당 연구가 이 벤치를 검증했다는 의미가 아니다.

R1 작동 검사는 R2의 다일 인간 비교를 대신하지 않는다. 같은 원자료를 이용한 독립 저작팀 검증도 저작 민감도를 확인할 뿐, 새로운 독립 고객 사례 수를 늘리거나 일반적인 FDE 능력을 단독으로 입증하지 않는다.

## 벤치마크 목적 정정 — 2026-09-08

R0 복구와 R1 작동 검증을 벤치마크 개발의 종착점처럼 설명한 것이 추가 오류였다. 사용자 목적은 AI 발전에 따른 모델·에이전트·하네스의 성능, 재귀개선 가능성, 실제 FDE 대체와 AGI의 관계를 시험하는 것이다. README에 요소별 대조와 시스템 전체 비교, 자기개선 세대·개선 주체·비용·보류 평가, 인간·현장 비교를 구분해 적었다. 공통 실행기와 실행 원장에 기반한 평가 패키지는 첫 사용판의 완료 조건이다.

이는 요구사항 정정이며 새 구현·재귀개선 성공·벤치마크 완성 보고가 아니다. R0–R3의 주장 수준과 개발 진행을 구분하고 인간 비교의 보류를 벤치마크 중단으로 해석하지 않는다. FDE 대체는 시험할 가설이며 인간 고유성이나 AGI 충분조건을 전제로 삼지 않는다. 기존 R0·R1 도구의 검사 결과는 이 새 요구사항을 검증하지 않는다.
