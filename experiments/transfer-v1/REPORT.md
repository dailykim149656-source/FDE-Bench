# 새 사례 전이 실험 결과

고정된 세 지시문 모두 새 합성 재고 사례의 품질 조건을 충족했다. **전이는 관찰했지만 수정 지시문의 우위는 확인하지 못했다.** 기존 라우팅 사례에서는 수정 지시문 실행의 처리량이 낮았다.

## 관측 결과

| 지시문 | 새 재고 사례 품질 checkpoint | 기존 사례 정확한 처리 | 기존 사례 SLA 내 정확한 처리 | 기존 사례 미처리 |
|---|---:|---:|---:|---:|
| 원래 지시문 (`ancestor`) | 9/9 | 280 | 180 | 0 |
| 업무 중립 (`neutral`) | 9/9 | 280 | 180 | 0 |
| 기존 개발 기록으로 수정 (`source_revised`) | 9/9 | 237.33 | 156.33 | 42.67 |

재고 checkpoint는 3개 workload seed × 3개 구간이다. 각 시점의 재고가 정확하고, 해당 구간의 오래된 값 쓰기·중복 쓰기가 모두 0이어야 충족한다. 기존 재고 정책은 이 조건을 0/9 충족했다. 세 에이전트는 모두 event ID 중복 억제, revision 순서 검사, 절대값 반영, 영속 상태를 배포했다.

라우팅 수치는 한 번 생성·고정한 정책의 구간별 결과를 합한 뒤 평가 seed 3개에서 평균한 값이다. **조건별 에이전트 실행은 1회**이므로 평균적인 에이전트 성능이나 통계적으로 확정된 회귀를 뜻하지 않는다.

수정 지시문의 정책은 문구 변화 구간에서 청구 요청을 수동 큐로 보냈다. 평가 원장의 미처리는 seed별 44·40·44건이었다. 개발 replay에서도 미처리 43건이 보였지만 해당 실행은 수정 없이 배포했다. 이는 이번 실행에서 관측한 실패 경로이며, 지시문이 언제나 같은 실패를 유발한다는 결론은 아니다.

## 실행과 증거

`gpt-5.5`에 세 지시문을 각각 두 사례에서 실행했다. 모든 개발 세션과 배포 정책을 먼저 고정하고, 이후 seed 701·702·703에서 기존 정책과 동일 workload로 평가했다. 신규 사례 구현 전에 지시문을 고정했으며 최종 평가를 본 뒤 재시도하거나 지시문을 수정하지 않았다. [방법과 실행 명령](README.md), [최종 실행 설정](registration.execution.json)을 함께 제공한다.

6개 세션 모두 배포하고 종료했다. 재고 사례의 원래·중립 지시문에서 각각 한 번씩 `unexpected_policy_payload` action 거부가 발생했고 이후 복구했다. 따라서 CLI는 기록된 오류를 보존하는 `completed_with_agent_failures`와 종료 코드 1을 반환했다. 실행 엔진 중단이나 정책 도메인 불일치 오류가 아니다.

모델 가용성 검사에서 원래 지정한 `gpt-5.4`가 지원되지 않아 사례 실행 전에 모델을 변경했고, 동시 실행 상한 2개도 실행 전에 기록했다. 원래 기록과 변경 기록을 모두 보존한다. 이는 외부 사전 등록이 아닌 로컬 기록이며 모델 이름도 불변 공급자 스냅샷 인증은 아니다.

[자동·수동 확인 기록](verification.json): 테스트 56개, Ruff, 타입 검사와 CLI 정상·실패 경로를 확인했다. [산출물 감사](artifact-audit.json): SQLite 72개 무결성, 구간 원장 해시 108개, 지시문·배포 정책·실행 설정 해시, 정책 고정 전후 파일 순서를 확인했다. 재고 품질은 저장된 효과·정답 테이블로 다시 계산했다. 이는 구현팀의 일관성 검사다.

평가기 소스 SHA-256: `aaca9e0c866b3800fcdec2d17cf874cb76dd40cb6bed7580bc6a16dd4d2fd025`.

[evidence_bundle.zip](evidence_bundle.zip)에 원 결과, 세션 기록, SQLite 원장, 고정 기록, 실행 패키지와 파일별 해시를 보존했다. 결과의 database_path는 원 실행 위치를 기록하며 압축 안에서는 같은 상대 경로로 찾을 수 있다. 모델 호출의 재실행은 확률적 결과와 계정 사용량을 수반한다.

## 이 결과가 말할 수 있는 범위

- 새로 저작한 합성 메커니즘으로의 적응 성공을 관찰했다. 독립 실제 고객 사례는 여전히 0개다. 사례 제작 작업자는 고정 지시문을 보지 않았지만 독립 연구팀 검증은 아니다.
- 새 사례는 세 조건 모두 성공해 변별력이 부족했다. 개발·평가가 전송 패턴을 공유하고 좁은 설정 공간을 사용한다. 9개 checkpoint를 9개 독립 사례로 세지 않는다.
- 모델·하네스는 고정했다. 모델 발전의 비교, 재귀개선의 이득, 인간 FDE 대체, AGI는 검증하지 않았다. 재시작은 연결 재개와 임시 metadata 소실의 모사이며 운영자 시간은 합성 비용이다.

ARC-AGI 연구자에게는 “검증된 일반 지능 벤치마크” 대신 **새 사례 전이와 기존 사례의 회귀를 실제로 관측한 파일럿**으로 제시할 수 있다. 다음 실험의 질문은 더 어려운 독립 메커니즘과 반복 실행에서도 차이가 유지되는가다. 이번 평가를 개발 자료로 재사용하면 이후에는 새 holdout이 필요하다.
